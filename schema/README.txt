STRUCTURAL SCHEMAS — ZTI-MCP 0.1 CANDIDATE

zti-common-0.1.schema.json: identifier, exact uint64 text, safe NumericDate,
digest, quantity, constraints and root-policy definitions.
zti-action-0.1.schema.json: Action_Binding envelope.
zti-mandate-0.1.schema.json: immutable zti_mandate body.
zti-mandate-claims-0.1.schema.json: signed-mandate JWT claims, before JWS encoding.
zti-ict-claims-0.1.schema.json: ICT JWT claims, before JWS encoding.

These five files are structural candidate schemas in the 2020-12 dialect. Their
JSON syntax and local references were checked; a complete JSON Schema engine was
not installed. They do not verify JWS signatures or canonical JSON. JCS hashing,
NumericDate order/TTL, parent and root equality, unit/dimension equality, inherited
constraints, issuer/key trust and live transactional state remain semantic checks.
An allowed set can be empty and then grants no rights. The uint64 regex expresses
the full 0..18446744073709551615 bound and disallows alternate decimal spellings.

zti-control-0.1.schema.json, when present, belongs to the coordinator's documentary
control/binding layer. It is not generated by export_examples.py. No file here is
evidence of MCP negotiation, transport compatibility or a certified deployment.
